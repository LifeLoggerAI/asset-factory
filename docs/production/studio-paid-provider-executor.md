## Protected configuration and exact identity

The executor requires an explicit HTTPS `ASSET_FORGE_SPEND_GATEWAY_URL`, a protected worker bearer `ASSET_FORGE_SPEND_WORKER_TOKEN` of at least 32 characters, and `FACTORY_STUDIO_SPEND_JOB_IDS_JSON`, a mapping of exact submitted request digests to existing protected job IDs. A map entry is routing, not approval. Missing/invalid configuration, response, build provenance, or admission blocks the provider request. Redirects and gateway retries are forbidden.

`URAI_SOURCE_SHA` (or `ASSET_FACTORY_EXACT_HEAD`) must match actual Git HEAD in the worker's repository. All four protected source paths must be tracked and clean. The worker rechecks its source and input before preflight, before reserve and immediately before provider submission. The deployed service must supply an immutable, independently verified exact build; declaring an environment SHA or pointing at a clean source checkout cannot alone prove which compiled bytes are executing. A deployment without actual checked source provenance stays closed. An owner must supply that protected runtime rather than bypass the check.

The gateway currently requires one matching `source_sha` for worker, gateway and enforcement proof. Admission therefore requires one deliberately converged source and coordinated exact-source deployment. Neither this isolated donor's SHA nor a different consumer's old gateway SHA can be used to authorize the combined runtime.

The job must name `consumer="factory-studio"`, the actual provider and exact model, `rights_reviewed=true` under genuine protected authority, and `authority={repository:"LifeLoggerAI/asset-factory",sha:<actual exact source>}`. Server validation and genuine approval remain required; the client does not turn the rights boolean into legal authority.

All executor fields and input fixity are covered by the canonical signed job digest. The client sends the four credential/header/input/content-type bindings with preflight, reserve and outcome observation. It derives `account_id` from the verified envelope, checks the protected account's verified credential mapping and receipt, and requires `envelope.protected_controls` to match the same actual account and all four fields. The canonical gateway independently verifies these bindings before each action. Before dispatch, the client compares the reserved account and all four echoes, then submits the captured POST method, header snapshot and frozen bytes. Mutating the caller's request while preflight is in flight cannot replace that admitted request. The full admitted binding is retained for outcome observation.

`envelope.protected_pricing` must name the exact provider/account/model/request and all four transport fingerprints, be a trusted protected readback with a nonempty receipt and fresh complete ISO `observed_at`/`expires_at`, and contain rates exactly equal to `job.budget.rates`. Rate verification and expiration must also be fresh and the rate receipt nonempty. The same local checkpoint requires a fresh trusted source authority whose binding equals the approved authority, fresh account and control observations, a control proof receipt, exact shared enforcement source/endpoint/request, enforced cash/credit/runtime caps equal to the signed budget, supported hard stop, and disabled auto top-up. The client rechecks all these proofs before reserve and immediately before dispatch; expiration of any authority/account/control/pricing proof while reserve is in flight blocks the provider and retains the hold. The gateway independently rechecks actual protected proofs before every worker action, including outcome observation. Matching rates or a receipt string alone cannot authorize a provider call.

Source JSON sorting is separate from the ASCII/integer job canonicalization matching Labs #229 and Factory #436; source prompts/metadata never become public receipts. Stability multipart requests use deterministic frozen bytes. OpenAI and ElevenLabs require explicit voice identities; no stock voice is silently selected. fal/Runway video require a named exact model and submit it in their endpoint payload. ## Attempts, continuation and unknown outcomes

One async execution session can issue one paid POST. The protected account transaction prevents a requeued/repeated session reopening the same job. A prior failed worker observation, local failure, missing task ID, lost reserve response, expired lease, timeout, successful response, or output artifact never releases the account hold. The original job's genuinely approved retry can proceed only after the canonical gateway verifies the independently signed final charge receipt and corrective action.

The reservation's runtime must exactly match the signed job's runtime and spans reservation, submission, response parsing, status polling, artifact retrieval and decode. Its conservative local deadline starts before reserve, so a delayed reserve response cannot restart or extend the signed runtime. Continuations are GET-only and use that same abort/deadline. Credential-bearing status requests must remain on the admitted provider origin. Replicate requires canonical `https://api.replicate.com/v1/predictions/<same task ID>`; Higgsfield requires its exact same-request status path. Neither status response may replace the admitted task identity. Artifact GETs carry no provider credential, reject redirects/private endpoints and retain configured byte limits; voice, video and JSON bodies are bounded while streaming. Gateway failure to record a successful result blocks its return. Failed observation transport leaves the reservation unresolved. Reports send only outcome/task identity, never actual-cost assertions, response bodies, prompt contents or private source media.

A local deadline can stop the worker and retain funds; it cannot establish remote-task cancellation or a financial hard cap. Current tested provider/proxy cash/credit/runtime stop, cancellation and kill-switch proof remains required in the canonical protected controls. Unknown remote outcomes retain the full cap until authentic reconciliation. Runtime acceptance must verify these real controls before any paid canary.
