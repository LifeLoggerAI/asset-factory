# Protected image spend executor

This corrective donor binds the existing Python image executor to one authenticated gateway in the existing Asset Factory Studio service. It does not authorize a real job, supply a balance, activate a provider, replace Model Forge, or claim deployment.

On main `a49f611ade29a1754787701ab4bf915c85c0cdc6`, a synthetic transport reproduced two provider invocations after auto fallback while `paid_request_guard` reserved only one call. The repaired provider leaves reserve once against the exact POST endpoint and bytes; implicit paid retries are removed. Auto fallback now renders locally without another provider invocation. Existing exact-version and Before Rest World wrappers consume that leaf reservation instead of reserving twice.

## Protected handoff

Python `paid_request_guard` requires an explicit HTTPS `ASSET_FORGE_SPEND_GATEWAY_URL`, a protected `ASSET_FORGE_SPEND_WORKER_TOKEN` of at least 32 characters, and `ASSET_FORGE_SPEND_JOB_ID` or an exact request-digest-to-job mapping in `ASSET_FORGE_SPEND_JOB_IDS_JSON`. There is no temporary-file, run-directory, environment approval flag, stale-lock deletion, or local-wallet fallback. HTTP redirects and ambiguous gateway calls are never retried automatically.

The gateway is `/api/worker/production-spend`. It requires the dedicated project in `ASSET_FACTORY_FIREBASE_PROJECT_ID` to agree with both `FIREBASE_PROJECT_ID` and the actual Admin Firestore project. Legacy/shared projects from the existing production-authority boundary are rejected. `URAI_SOURCE_SHA` must identify the deployed exact source, and must equal `job.executor.source_sha`, `controls.enforcement_source_sha`, and the caller's `executor_source_sha` before preflight or reserve. The Python caller checks its actual Git HEAD against declared `URAI_SOURCE_SHA` (or `ASSET_FACTORY_EXACT_HEAD`), requires all four protected image source files to be tracked, and rejects dirty source before requesting admission. Missing Git provenance fails closed. Gateway deployment must provide an immutable, independently verified build identity; an arbitrary environment string is not real deployment proof. Worker and reconciliation bearer credentials are separate protected configuration. Missing auth/configuration fails closed even outside production; legacy headers and disabled asset-auth modes do not admit spend.

The gateway reads server-only records. Root and Studio Firestore rules already deny client access to these unmatched collections; real deployed rules and Admin IAM still require readback before activation. The existing Factory service and image executor are the canonical target, under the Asset Factory/protected executor owner. This isolated donor does not mutate active PR #421 (Model Forge/source preparation) or #306 (provider receipt authority); those owners must admit or coordinate downstream use. App credentials must remain confined to this protected execution service. Public clients, provider workers, and users must never receive arbitrary Firestore Admin write capability or private signing keys.

`job.executor` binds `source_sha`, `controls_ref`, `endpoint`, `asset`, `request_size`, and `request_sha256`. The request hash is SHA-256 of UTF-8 `POST\n`, exact endpoint, `\n`, and the exact submitted request bytes. The job digest includes this complete executor identity and all job fields except approval and mutable attempts, matching Labs #229.

Protected `ASSET_FACTORY_SPEND_APPROVER_PUBLIC_KEYS` and `ASSET_FACTORY_SPEND_RECONCILER_PUBLIC_KEYS` are JSON maps from key ID to `{subject, publicKey}`. Private signing keys stay with the authentic approver/reconciler. Canonical signing serialization is the exported `canonical()` function, with `signature` excluded. This donor does not create signatures for real work or treat synthetic test signatures as authority.

The worker first requests a non-authorizing fresh envelope, runs the pinned offline checker, and submits its job digest to the atomic reserve action. The transaction rereads current source, signed approval, pricing, controls, account reservations and attempt state. Competing workers and distinct jobs contend on the same account document. A pending/lost/successful/cancelled attempt cannot open another provider call. Only a final independently signed failed charge receipt with a reviewed corrective action can enable the originally bounded single retry. A retry preserves the full original job hold and checks accumulated actual charges against the remaining cap.

Worker outcomes only move the durable attempt to `RECONCILIATION_REQUIRED`; they cannot release funds, supply actual prices, or authorize retry. Final reconciliation records actual charges. Terminal jobs replace their full cap reservation with actual debit hold against that same balance snapshot. Those debits deliberately remain held across fresh snapshots until explicit governed account reconciliation removes already-accounted debits; the donor contains no implicit reset. This can overcount temporarily, but prevents stale snapshots reopening consumed cash. Actual overruns are retained truthfully and freeze the account.

The Python leaf enforces a main-thread wall-clock deadline over network, artifact retrieval and normalization, and refuses platforms without the interval timer. The gateway additionally requires current proof of actual provider/proxy hard runtime and financial enforcement. Direct OpenAI timeout alone is not that proof. Artifact retrieval also requires HTTPS, disables redirects and bounds each response to 64 MiB. No provider is enabled by this donor. Synchronous network execution and already-created remote tasks remain subject to the provider control receipt; uncertainty holds the entire cap.
