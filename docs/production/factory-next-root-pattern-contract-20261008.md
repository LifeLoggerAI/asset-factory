# Next root-directory consumer contract

The Next 16.3.8 ESLint plugin's literal `getRootDirs` caller is preserved: default cwd, string normalization, arrays, non-string filtering and concatenation retain their upstream behavior. Its directory-only glob call is routed to `dist/utils/urai-next-root-glob.js`. This is a bounded implementation of that specific caller, derived from fast-glob 3.3.1's MIT directory/task/partial-match behavior. The exact MIT notice is installed beside the helper. It exposes only `rootDirectories`, not a general glob API.

The implementation uses explicit pinned modules: `@nodelib/fs.walk1.2.8`, `glob-parent5.1.2`, `picomatch2.3.2` and maintained `brace-expansion5.0.12`. It does not load fast-glob, micromatch, braces, glob or glob's bundled runtime. Matching options, static-before-dynamic task grouping, stable expanded-pattern length ordering, path formatting, default symlink handling, partial positive traversal and negative subtree pruning follow the original caller. Returned arrays are compared without sorting. Entry exclusions and negative traversal exclusions deliberately retain their different original dot/trailing-slash rules.

Brace preparation preserves the original bounded quote, alternative and range mechanics before using the maintained expander. Quoted groups stay literal; quotes around range endpoints/steps retain their original AST effects. Numeric coercion, signed/padded endpoints, step-width padding, Unicode/mixed letter ranges, comma alternatives and literal malformed braces retain the original tested results and errors. An unquoted decimal start is literal; a decimal finish or quoted decimal start can expand. An unquoted decimal numeric step retains the original RangeError. Malformed Bash-style brace rewriting cannot silently select additional roots.

Resource inputs are intentionally fail-closed before filesystem access. Limits are 65,536 input/prepared UTF-16 units, 128 structural nesting levels, 1,024 groups/closings, 1,000 results per range, 10,000 expanded alternatives and 3,000,000 cumulative expanded UTF-8 bytes. Non-progressing zero steps, noninteger/unsafe steps, unsafe range endpoints and NUL inputs reject with TypeError. Matched quote spans are identical in preflight and preparation; unmatched quotes cannot hide active nesting. Expander count/length ceilings reject instead of accepting a truncated set. These limits bound CPU/memory work; they do not promise parity with an original process crash or arbitrary inputs outside this contract.

`test-next-root-dirs-exact-differential.mjs` exercises the actual installed literal helper and exact maintained dependencies. It compares 215 ordered directory cases and 388 private expansion cases against exact upstream Next16.3.8/fast-glob3.3.1 and retains 52 fixed expected regressions (37 quote/range boundary and 15 negative-traversal cases). The private expansion function is exposed only in VM test memory; installed production bytes/API stay unchanged. Twenty-nine malformed/resource cases run under a 128 MB heap and require TypeError before any stat or walk. Synthetic fixtures contain no accounts, credentials or provider data.

The pinned upstream oracle is installed outside the candidate workspace solely for finite comparisons. It is not added to the production frozen graph; adversarial inputs are never replayed through its vulnerable parser. Source-fixture comparisons do not certify the whole installed workspace. The native workflow must install the committed frozen workspace, verify every installed consumer file/dependency and the complete graph, run both compatibility suites, execute unchanged launch readiness with the actual Studio compiler, run Studio lint/types/build and preserve actual depcheck findings. Both complete reviewed advisory gates remain mandatory and unchanged.

Independent mechanical source review of these bounded cases is separate from genuine human release review, current combined-head native acceptance, deployment/provider acceptance and the sole #421 release gate.
