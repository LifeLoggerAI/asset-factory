# UrAi reusable generic world candidates

This isolated Model Forge subtree manufactures original metric architecture and furnishing candidates for the Generic World Library in Studio #153 and the offline queue in Jobs #152. It does not change Spatial, final-asset resolution, admitted source authority, providers, deployments, or release candidates.

The source specifications live in `LifeLoggerAI/urai-studio`, under `productions/generic-world-library/v1`. Their raw SHA-256 identifies each source brief. These builds are **partial realizations**: actual manufactured dimensions, object counts, secondary spaces, materials and profile files are recorded in each package. A broader source brief or variant list does not prove every requested variant is generated.

## Actual output and status

The current build version is **1.0.2**. `receipts/build-index.json` inventories twelve Batch 1 families plus bedroom, office and warehouse candidates, and twelve reusable furnishing/architecture modules. Each composed world has desktop `lod0.glb`, XR design-profile `lod1.glb`, mobile design-profile `lod2.glb`, conservative collision GLB, planar navigation metadata, lighting settings, cameras, source identity, provenance and dependency hashes.

GLBs contain actual original geometry, base-color/normal/roughness/metalness maps, UVs, explicit tangent space and bounded material batches. They contain no real person, private source media, invented identity, branded signage or third-party source asset. This is authored procedural content with bevels, panel construction, manufactured details and metric dimensions, rather than a provider-generated photographic scene. It is **not AAA art accepted**.

## Reproduce or verify

Python requires NumPy and Pillow; the verified execution used NumPy 2.3.5 and Pillow 12.3.0. Source specifications must be checked out alongside this repository as `../world-factory-studio` for generation. Version directories are write-once: the builder refuses to replace an existing version. A later build must increment `VERSION` and retain predecessor receipts.

```bash
python3 model_forge/generic-worlds/v1/build/build.py
python3 -m unittest discover -s model_forge/generic-worlds/v1/qa -p 'test_*.py'
python3 model_forge/generic-worlds/v1/qa/run_all.py model_forge/generic-worlds/v1 --version 1.0.2 --report /absolute/new/qa.json
npm ci --ignore-scripts --prefix model_forge/generic-worlds/v1/build
node model_forge/generic-worlds/v1/build/khronos.mjs /absolute/repo/model_forge/generic-worlds/v1/build/node_modules/gltf-validator 1.0.2 /absolute/new/validation
```

Actual world validation requires verified asset bytes at the documented relative package/kit paths. Check the archive before extraction with `qa/verify_staging.py`; that tool does not extract files, resolve runtime assets or make promotion decisions. Never overwrite an existing version while materializing a candidate. A source-only clone can run the 75 rejection tests and `qa/check_repository.py`, which verifies original code hashes and boundary labels in the compact summary. CI does exactly those checks and does not claim it retested archived geometry, rendered scenes or physical devices.

The isolated rendering harness uses Three.js 0.180.0, a local Chromium executable and Playwright. `render.mjs` takes absolute tool/browser paths and renders six views per world: wide technical cutaway, eye height, doorway, detail, mobile LOD and XR LOD. A technical cutaway deliberately hides the front wall, ceiling and door for layout review; it is not an ordinary first-person runtime screenshot. Mobile/XR pictures are design-profile renders on the same software browser, not physical-device certification. The review harness adds a neutral Three.js RoomEnvironment and lights; those are separately recorded review conditions, not baked lighting in the asset.

```bash
node model_forge/generic-worlds/v1/build/render.mjs --version 1.0.2 --tools /abs/node_modules --browser /abs/chromium --playwright /abs/node_modules/playwright
```

## Collision, navigation and personalization

All geometry is glTF right-handed, +Y up, asset front +Z, camera forward -Z, in meters. Vertices are baked with identity node transforms. Scene origin is floor center; all bounds and anchor coordinates are explicit. Inserts start with identity translation/quaternion/scale. A real scan or splat must retain source unit/axis conversion and measured alignment separately.

Navigation cells are conservatively sampled flat floor polygons, with furniture/wall AABBs expanded for an agent. Entry, return landmark and collision-clear reachable teleport centers are recorded. This is not a Recast bake, full disk/headroom proof or a tested movement controller. Some sampled cells can be disconnected. Full runtime movement, controller behavior, safe landing disks, wheelchair/reach clearances and physical XR comfort require later checks. Simple rounded furniture uses conservative box collision. Fine props and glazing need runtime collision/occlusion review.

GLB category batches and semantic part names support later recomposition; full empty/rich packages are not separately emitted. Furniture substitution, photo/object attachment, source scan insertion, memory anchors and lighting variants remain governed operations. The generic shell must remain `GENERIC` even when an independently authorized recorded/reconstructed insert is attached. No source consent, real-place claim or person identity may be inferred from a generic kit.

Existing Asset Factory promotion/resolution remains the integration owner. The future chain is candidate -> validate -> clean -> actual scene render -> literal acceptance -> approval -> governed promotion. No consumer URL, runtime resolver, asset admission flag or final manifest is changed here.

## Provenance and limitations

The geometry/material synthesis is original local work in this Apache-2.0 repository. No external asset bytes or license-dependent brands were imported. Retain the repository license and notices for redistribution. Studio source briefs separately record unassigned project-authored specification rights; that record does not license a nonexistent provider output. Provider outputs need their own actual creator/task/date/model/prompt/license/commercial-use evidence.

Known gaps include repeated procedural material tendencies, limited furnishing/clutter, absent photographic foliage/vehicles/audio/people, simplified institutional/outdoor subspaces, no photogrammetry or splat bytes, and no baked indirect light. Human visual/art judgment and governed reference assets are required before production art acceptance. Source-era and region labels are artistic options, not universal historical claims.

Only static budgets are measured. Hardware load/decode/frame time, runtime LOD switching, device memory, XR controllers and standalone-to-UrAi equivalence remain unmeasured. Software review frame timings cannot satisfy desktop/mobile/XR hardware acceptance. The packets spend nothing and submit nothing; actual provider execution requires credentials and bounded paid authority through existing Model Forge.
